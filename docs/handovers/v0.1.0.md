# Handover — avm-effectproof v0.1.0

**Status:** v0.1.0 complete — dual-chain, 16 tests green, CLI working. Independent review pending.
**Repo:** `chopmob-cloud/avm-effectproof`
**Scope:** reads effects out of an already-authenticated `SignedTxnInBlock`. Does **not** authenticate.

---

## 1. Why this repo exists

The A-series work in `avm-proofpack` proves that a transaction was **included** in a block.
It does not prove what the transaction **did**. For bridges, RWA cashflows and agent
payments, "the app call committed" is not the claim anyone cares about — "the recipient was
paid" is.

This repo closes that gap. It is the item I previously flagged as blocked on an unknown
protocol dependency; that dependency turned out **not to be missing**.

## 2. The decisive protocol fact (verified, not assumed)

- `data/bookkeeping/block.go`: `Block = BlockHeader + Payset`, and `TxnCommitments` lives
  **in** the header.
- `config/consensus.go`: from `v26` onward, `PaysetCommit = PaysetCommitMerkle`.
- `data/bookkeeping/txn_merkle.go`: the tree is *"a cryptographic commitment to the
  transactions in the block, **along with their ApplyData**"*; the leaf preimage is
  `Hash("TL" ‖ txid ‖ stib.Hash())`.
- `data/transactions/teal.go`: `EvalDelta` contains `GlobalDelta`, `LocalDeltas`, `Logs`
  and `InnerTxns []SignedTxnWithAD`.

Therefore: State Proof → BlockHeadersCommitment → block header → TxnCommitments → Merkle
leaf = the full STIB **including effects**. Effect proofs are possible today with no
protocol change. This is the fact the whole repo rests on — do not weaken it.

## 3. Dual-chain compliance (explicit requirement)

Every structural test runs against **both** chains, from real blocks:

| Chain | Round | Contents |
|---|---|---|
| Algorand mainnet | 63605124 | app 1439234347, 2 global writes, 3 inner (incl. 1000 µAlgo) |
| Voi mainnet | 181248 | app 5211, 2 logs, 5 inner (incl. 100000 µVoi) |

Two real cross-chain differences were found and handled — not assumed away:

1. **Binary fields arrive differently.** The same field is `bytes` on Algorand and a
   surrogate-escaped `str` on Voi. `_as_bytes` accepts both and round-trips with
   `surrogateescape`; without this, every Voi log raised.
2. **`ValueDelta` is a typed struct, not a bare value.** It is
   `{"at": 1|2|3, "bs": str, "ui": uint}` with a **1-based** enum
   (`data/basics/teal.go`: `SetBytesAction=1, SetUintAction=2, DeleteAction=3`).
   `0` is invalid, and `bs`/`ui` are omitted when empty — a set-uint of `0` arrives as
   `{"at": 2}`. A naive `{key: bytes}` assumption silently misreads state.

## 4. Files

- `src/avm_effectproof/effects.py` — `decode_stib`, `Effects`, `InnerTxn`, `StateChange`, `ChainProfile`
- `src/avm_effectproof/predicates.py` — `has_*` / `find_*` over top-level and nested effects
- `src/avm_effectproof/cli.py` — `avm-effectproof <stib> --describe|--check`
- `tests/test_effects.py` — 16 tests, parameterised over both chains
- `tests/fixtures/*.bin` + `*.json` — real STIBs with provenance metadata

## 5. Decisions

1. **Depends on `avm-proofpack` for msgpack.** The core is otherwise stdlib. Re-implementing
   a canonical msgpack decoder would add risk for no gain, and proofpack is already
   zero-dependency.
2. **Layering is explicit.** This repo never verifies inclusion; the README and docstrings
   say so in the first paragraph. A caller that feeds it an unproven STIB gets claims, not
   proofs.
3. **Local-state deltas stay as raw indices.** Resolving `ld` indices to addresses requires
   the transaction's account list and `SharedAccts`; v0.1 exposes the indices rather than
   guessing. Documented as a known limitation.
4. **Fail closed on unknown encodings.** An unrecognised `at` action raises; it is not
   skipped. Skipping would under-report effects, which is the dangerous direction.

## 7. What this does NOT do

- No inclusion proof — pair with `avm-proofpack`.
- No local-delta index resolution, no boxes, no app arguments.
- No trust tier; it is a decoder with predicates.

## 8. Next actions

1. Independent review (not yet done).
2. Wire the predicate layer into a receipt: `proofpack` bundle → authenticated STIB →
   `effectproof` predicates → a signed "effect receipt".
3. Add boxes and app-argument decoding once a consumer needs them.
4. Consider a conformance fixture per chain that exercises `ld` (local deltas) and a
   deletion (`at: 3`), which the current fixtures do not cover.

## 9. Constraints

- Never claim effects are proven without an inclusion proof.
- Keep both chains in the test matrix; a change that only passes on Algorand is a regression.
- Do not relax the `at` enum handling to be "lenient".
